Defects — ranked by threat to output trust

HighResearch grabbed the wrong entity (silent)

The research phase populated the company profile from a UK Companies House record for an unrelated 1990 company, not the AI advisor at stevecunningham.ai:

profile.description → "Steve Cunningham & Associates Limited was set up on Monday the 11th of June 1990…"

primary_industry → "Forrester: Global Technology Spend Will Grow By 7."  (a snippet headline, not an industry) · company_name → None

The output only stayed correct because the --context argument overrode the polluted profile during Gemini synthesis. Without a strong context string, this run would have produced a confident strategy for the wrong company. This is the real floor risk.

MedPPTX decks: 0/2, and the failure is swallowed

Both decks (executive_summary, full_findings) sit at status=pending. The orchestrator wraps generation in try/except _record_error, but state.errors persisted as [] — the exception text is lost. The whole generation phase ran in 2.7 s, too fast to have built decks.

Tracing the code path: the deck generator is tightly coupled to live pydantic objects (research.industry.primary_industry, synthesis.deliverables), and the exact in-run throw isn't recoverable from artifacts because synthesis_output isn't persisted to state. PPTX is broken on this build, and the error handling hides why.

Low · envMermaid PNGs are placeholders

All 4 .png files are byte-identical 5586-byte fallbacks. The .mmd source is real and good; rendering needs the mermaid CLI — npm i -g @mermaid-js/mermaid-cli (mmdc) — which isn't on this box. Pure dependency gap, not a code bug.

Also flagged: google.generativeai is deprecated upstream (Google wants google.genai). Works today, future-fragile.

Recommended next actions

    Protects every downstream deliverable. The root cause of defect #1.
  2. Stop swallowing the PPTX exception — persist it to state.errors so the failure is debuggable, then fix the deck generator. quick win
    The only thing standing between this and a complete 19/19.
  3. Install mmdc to light up the 4 diagrams — or swap to a Python-native mermaid renderer to drop the Node dependency entirely.
